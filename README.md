## 📱 التطبيق (PWA) والعمل دون اتصال

| الملف | الوظيفة |
|------|---------|
| `manifest.webmanifest` | تعريف التطبيق: الاسم، الاسم المختصر، رابط البدء، الوضع المستقل، ألوان السمة والخلفية |
| `sw.js` | Service Worker للعمل دون اتصال — الصفحات **NetworkFirst** والملفات الثابتة **CacheFirst**، مع استثناء مسارات المصادقة/OAuth. عند تعديل أي ملف غيّر `CACHE_VERSION` |
| `vite.config.js` + `package.json` | إعداد بديل بـ `vite-plugin-pwa` (نفس الاستراتيجيات) لمن يفضّل بناء Vite — يحتاج Node |
| `icons/` | `icon-192.png` · `icon-512.png` · `icon-maskable-512.png` (أندرويد) · `apple-touch-icon.png` (آيفون 180) |
| `make-icons.ps1` | إعادة توليد الأيقونات عند الحاجة |

**التثبيت:** أندرويد (Chrome) ← «تثبيت التطبيق» • آيفون (Safari) ← «إضافة إلى الشاشة الرئيسية».
**تنبيه مهم:** العمل دون اتصال يتطلب `https://` أو `localhost` — لن يعمل بفتح الملف من المجلد مباشرة (`file://`). عند النشر على GitHub Pages أو أي استضافة https يعمل تلقائياً.

## 🗒️ صفحة «ملاحظاتي» — إعداد Supabase

الصفحة `notes.html` تحفظ ملاحظات كل مستخدم في **حسابه** على Supabase (قاعدة بيانات + مصادقة)،
والحماية على مستوى الصفوف (RLS) تضمن ألا يرى أحد ملاحظات غيره.

### 1) أنشئ مشروعاً
Supabase Dashboard ← **New project**.

### 2) نفّذ ملف SQL
**SQL Editor** ← الصق محتوى `supabase-notes.sql` ← **Run**.
ينشئ جدول `notes` + سياسات RLS + Trigger لتحديث `updated_at`.

### 3) اضبط المصادقة
- Authentication ← Providers ← **Email** ✅
- Authentication ← URL Configuration:
  - **Site URL:** `https://mqdbbd.github.io/names-of-allah/`
  - **Redirect URLs:** `https://mqdbbd.github.io/names-of-allah/notes.html`

### 4) ضع المفتاحين في `notes.html`
```js
const SUPABASE_URL      = "https://xxxx.supabase.co";
const SUPABASE_ANON_KEY = "eyJ...";   // anon / public فقط
```

> ⚠️ **لا تضع `service_role` في الملف أبداً** — يتجاوز RLS ويكشف كل بيانات المستخدمين.
> مفتاح `anon` عام بطبيعته، والأمان يأتي من RLS.

### 5) اختبر
افتح `notes.html` ← أنشئ حساباً ← أضف ملاحظة ← اخرج ثم ادخل ← تظهر ملاحظاتك.
ثم جرّب حساباً آخر: لا يرى شيئاً ✅

## 💾 نظام النسخ الاحتياطي (Snapshots)

> ⚠️ **قاعدة إلزامية:** قبل أي تعديل على المشروع — مهما كان صغيراً — احفظ Snapshot:
> ```
> powershell -ExecutionPolicy Bypass -File .\snapshot.ps1 "وصف التغيير"
> ```
> وبعد الانتهاء من التعديل احفظ Snapshot أخرى تصف النتيجة. الغرض: إمكانية الرجوع
> لأي حالة سابقة إن حدث تغيير غير مرغوب فيه.

يحفظ المشروع نسخة مؤرشفة كاملة قبل/بعد كل تعديل، مع سجل مؤرخ في `CHANGELOG.md`.

```powershell
# حفظ نسخة قبل أي تعديل
powershell -ExecutionPolicy Bypass -File .\snapshot.ps1 "وصف التغيير"

# عرض قائمة النسخ المتاحة
powershell -ExecutionPolicy Bypass -File .\restore.ps1

# الرجوع إلى نسخة محددة
powershell -ExecutionPolicy Bypass -File .\restore.ps1 snap_2026-10-17_03-29-32
```

- تُحفظ النسخ في مجلد `snapshots/` باسم `snap_التاريخ_الوقت`.
- كل نسخة تحتوي ملف `_INFO.txt` فيه التاريخ والوصف.
- `restore.ps1` يحفظ نسخة من الحالة الحالية **قبل** الرجوع، فيمكن التراجع عن عملية الرجوع نفسها.
